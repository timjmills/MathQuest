# Spec card: The interactive lesson player (`lesson-player`): a new SCREEN that runs a lesson as Warm-up, I do, We do, You do and Exit ticket, on the board or self-paced

Generated by `node tests/scripts/ws-spec-card.mjs --template lesson-player` from `design/cards/lesson-player/card.json` and the repo. Do not edit by hand: edit card.json and regenerate. Builders read this card; critics keep reading the full standards and RUBRIC.

ONE player runs a lesson on screen in five parts, Warm-up -> I do -> We do -> You do -> Exit ticket, in two modes: Board (teacher-led, whole class, big type, presenter controls, reveal on click, saves nothing about pupils) and Pupil (self-paced, part reached and exit score saved). Every part is GENERATED from the lesson record the print packet already uses and dealt through generateQuestionFor with seeds, so a lesson replays identically and matches its printed packet. Every question region is the black-and-white Andika screen cell (SP-1, SP-2); everything coloured is chrome outside it (SP-30; INK-30 for the step numerals only). One pure function planLesson(lessonId, {seed, mode}) -> {parts:[{part, items, steps?, say?}]} deals everything; no part generates on its own (P-ON-2). Skills: none of its own; it plays every library lesson's skills (lesson.practice, lesson.warmup), first add-within-10 (addition:add_facts band 10, constant 1-3).

## 2. Problem types and progression

*From repo sources: PEDAGOGY_STANDARD section 11 (online modes mirror page roles, the hint ladder rungs 1-4, P-ON-1..8), WORKSHEET_DESIGN_STANDARD SP-1..SP-40 (screen parts), PAGE_TYPES PT-PKT-1 / PT-ANC-1 (packet parts, the anchor example), roles/lesson.js (the packet anatomy), the existing board display (teacher-shell.js tv-bigboard). Interactive grammar (IXL 'learn with an example', Boom Learning task-card reveal, presentation-clicker conventions): reveal one step per click, read aloud, then try one; ours keeps one boxed B&W cell and the Steps strip of the printed anchor chart.*

**Problem types**

- Warm-up: 1-3 cells, one per prerequisite skill (lesson.warmup, else routine.skills), each with its library instruction and its own input; feedback on Check; unscored; Board: Show answer per cell; a miss shows the Prerequisite Check's 'If missed -> Lesson ...' line in chrome.
- I do (step reveal): state k of n = the cell redrawn as after step k (provider workedSteps + anchors.js stepState; P-LC-9: step k marks grey, earlier black), the step's own sentence under the drawing (L6), Steps strip row k outlined, later rows grey; Next reveals k+1, Back returns; no input. After the LAST step the Say band (BD-8, full width under the cell, cell ink) shows the real filled Say line (sayLineOf, e.g. 'Say: 6 plus 3 equals 9.'), read once; then 'Say it together' (chrome) waits. The routine's chant, if any, under Say.
- We do (hint fade): 2-3 items (routine.guided cases via pickWeDo, else the practice skill) at level 2 (P-LC-7); item 1 at rung 1 (next step's marks grey + sentence), item 2 rung 2 (sentence), item 3 rung 3 ('What comes next?' + Steps row highlighted); a correct item moves the next one down a rung, a wrong Check keeps it (P-ON-7); a hint never fills a slot (P-ON-8); live per-digit feedback (SP-31). Board: teacher drives the rung with Hint / Next.
- You do: the existing practice-card host embedded unchanged (D9): 6 items of lesson.practice (practiceBlocks[0] opts if present), Check, Skip, wrong-retry, end-of-run, hint ladder on request.
- Exit ticket: 3 items of the practice skill (one per routine case where there are 3; a detailed lesson's 'exit' skill), Test level (scaffold 0, hints off, on Check once, no retry), score n/3 with accuracy only (P-ON-4); saved per D7; 0-1/3 shows 'Re-teach: replay I do' (chrome).

**Progression** (one new thing per step, P-1)

1. Part order is fixed (P-1, P-ON-1): Warm-up -> I do -> We do -> You do -> Exit ticket; any part reachable from the part rail; repeat or skip any part.
2. Scaffold fades across the parts: I do level 3 (worked) -> We do level 2 with rungs 1 -> 2 -> 3 -> You do level 1 (hints on request) -> Exit level 0.
3. Build slices, smallest first (D8): 1 planLesson + I do, Board, add-within-10, URL launch; 2 Warm-up + We do, both modes; 3 You do + Exit ticket + save + dashboard row; 4 launch buttons, detailed lessons, every library lesson swept.

### 4a. Core rules — apply every one (10 rules; ✱ = quoted in full, the rest cut at a sentence)

**Screen cell (quoted)**

- **SP-1** (WDS) The on-screen question region is the same cell: same template, same SVG builders, same Andika, same ink rules, same line-style semantics, same slot shapes, same label style, problem in the top half, response pinned in the same place.
- **SP-2** (WDS) Inside `.ws-cell` everything is `--ws-ink` on `--ws-paper` with square corners, **in light and dark theme alike**. The `.mq-mono` scope applies to every visual host listed in SC-1.
- **SP-3** (WDS) Parity of task: the screen never converts a production item into multiple choice unless the paper item is a choice. Each print response mode has one screen twin (`design/PROBLEM_TYPES.md`).
- **SP-10** (WDS) Minimum touch target 44 x 44 px for every input, option, check box, part-to-shade and box-to-tap; digit inputs are at least 48 px tall. The only exception is a 10-column chart on a phone: 34.5 x 44 px. …

**Teaching sequence (quoted)**

- **P-1** (PED) **One new thing per step.** Compared with the same page role of the previous step, exactly one of these changes: `range` (number size or the fact set), `representation`, `format` (vertical / horizontal / notation), `unknown` (position of the unknown), `opMix` (which operations appear), `scaffold` (one support …
- **P-17** (PED) **Every Model ends with an oral frame.** A fixed sentence with blanks that the pupil reads aloud with the numbers in ("__ plus __ equals __."). Pupils state the steps and the result; they are not asked to explain their thinking in open speech. Online, the frame is the "Say it" line spoken by text-to-speech. …
- **BD-8** (WDS) **The `Say:` band** is an official band of the lesson opener: a full-width strip directly under the Model and Steps zones, closing the Model band. It is a print-dialog option, **on by default**; switched off, its height returns to the body (PG-4). Geometry: height Hw + 3 = 9 / 11 / 13 mm …
- **P-LC-9** (PED) Algorithms with 3 or more steps also get a **scripted Model page**: one problem redrawn once per step, left to right and top to bottom; in each redraw only the newest marks are grey, all earlier marks are black; the step's sentence sits under its redraw.
- **P-ON-1** (PED) Learn runs 3 → 2 → 1 on the same step with the same cell. The default counts mirror the Opener: 1 worked, 1 worked-along, 2-4 guided, then 6 independent. The pupil or teacher can repeat or skip any part; nothing is locked.
- **P-ON-7** (PED) Learn 2 starts at rung 1 and moves down one rung per item answered correctly. In other modes a hint request opens rung 2, a second request rung 1. After two wrong Checks on one item, the app offers "Show me" (rung 1 for that item) and offers the next item at one scaffold level higher in the same format (P-24).

## 6. Misconceptions

For answer keys, `wrongAnswer`, error analysis, True or False? and Reason It (P-TH-13).

- **M-LP1** the player invents steps a provider does not give (workedSteps with 1 or 0 steps) — e.g. a generic 'Think. Work. Check.' reveal
- **M-LP2** the screen example differs from the printed anchor chart for the same seed — e.g. I do 5 + 2 on screen, 6 + 3 on the chart
- **M-LP3** a hint writes into the answer slot (P-ON-8) — e.g. rung 1 shows 9 in the box
- **M-LP4** the board saves the class's answers as one pupil's exit score — e.g. a 'Lesson exit 3/3' row from the board
