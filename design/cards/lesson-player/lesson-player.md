# Spec card: the interactive lesson player (`lesson-player`), a new screen

Lane **lf-hosts**. Kind: **screen** (not a template or family card, so it is hand-written, not generated by
`ws-spec-card.mjs --template/--family`; see §10). Written 2026-11-20 at medium effort (first card for a new screen,
CLAUDE.md "Agents"). **UNSIGNED.** Nothing is built until the lead signs §11.

Mock: `design/cards/lesson-player/mock-ido-board-1280.html` + `.png` (I do, board mode, 1280 x 800, dsf 2).

## 0. What it is, in one paragraph

ONE player that runs a lesson on screen in five parts, **Warm-up -> I do -> We do -> You do -> Exit ticket**, in two
modes: **Board** (teacher-led, whole class, big type, presenter controls, reveal on click) and **Pupil** (self-paced,
progress saved). Every part is GENERATED from the lesson record the print packet already uses (`lessonData()` /
`engineRecord()` in `js/modules/lessons/library.js`) and dealt through `generateQuestionFor` with seeds, so a lesson
replays identically and matches its printed packet. Every question region is the existing black-and-white Andika
screen cell (`screen-cell.js`, `.mq-scell`, SP-1/SP-2); everything coloured is chrome outside it (SP-30, INK-30 for
the step numerals only).

## 2. Data source and generation (decision D1, D2)

**Primary source: the library lesson** (`lessonById(id)` + `lessonData(id)`; 45 lessons today, e.g. `Y1.B2.S9`
slug `add-within-10`). The 7 DETAILED lessons (`data/curriculum/detailed-lessons.json`, `js/modules/lessons/detailed/`)
join in slice 4 through their `skills.used[].role` tags (main / P0 / P1 / exit).

| Part | Record fields that drive it | Dealt by |
|---|---|---|
| Warm-up | `lesson.warmup[]` (`{key, opts, why}`), else `routine.skills[]`; 1 item per prerequisite skill, max 3 | `generateQuestionFor({category, skill, opts, seed: S+100+i})` |
| I do | `lesson.practice` (skill + opts) dealt and filtered by `routine.example` (`match` / `test` / `prefer`, the same `pickExample` the anchor chart uses, `roles/lesson.js`); steps = provider `workedSteps(q)` (one screen state per step, `stepState` from `sheet/anchors.js`); step names + icons = `routine.steps[]`; Say = `sayLineOf(it)` (provider `strings.sayFill` / `say` frame); Rule = `routine.chant` if any; `routine.notes[i]` under step i | the anchor's own example: **identical to page 1 of the printed packet** |
| We do | 2-3 items: `routine.guided` cases in order (`pickWeDo`), else the practice skill; level 2 (P-LC-7) | seeds S+200+i |
| You do | `lesson.practice` with `practiceBlocks[0]` opts if present; 6 items (P-ON-1 default) | seeds S+300+i |
| Exit ticket | 3 items: the practice skill at its lesson opts; for a detailed lesson, the skill whose role says `exit`; one per `routine.cases` where 3 cases exist, else the default case | seeds S+900+i |
| Title / tags | `iCan` of the provider (as the packet), `tagLine()` (skill, grade, CCSS, EE) | - |

**Seed S** = the packet seed (`buildSheet` `seed`) for the lesson; default `hash(lessonId)` so the board and every
pupil see the same lesson. "New numbers" in Board mode bumps S by 1 and shows the seed in the teacher footer
(same convention as print's "Form A · seed N"). Replay = same S, same items, byte-identical cells.
The player calls ONE pure function `planLesson(lessonId, {seed, mode})` -> `{parts:[{part, items:[q], steps?, say?}]}`;
no part generates on its own (P-ON-2). That function is unit-testable in node (no DOM).

## 3. The two modes (D3, D4)

| | **Board** (teacher-led) | **Pupil** (self-paced) |
|---|---|---|
| Launched from | Teacher shell: the lesson's row in the Lessons / WRM area and the lesson print screen get a **"Teach on board"** button; opens in the existing board display (`body.tv-bigboard`, `?board=1` window, teacher-shell.js) | Student explorer / Quick start: a **"Lesson"** card for any skill with a `defaultFor` lesson; also a share link `?lesson=<id>&s=<seed>` |
| Type | Board scale: digits 96-112 px at 1280, x1.5 at 1920 | Card scale (`.mq-scell` 40-56 px digits) |
| Advance | Reveal on click / key / clicker; teacher owns the pace; nothing scores | Pupil presses Next; I do auto-reads each step |
| Answers | We do / You do: the teacher types the class's answer, or taps **Show answer**; feedback shows | Pupil types; live / on-Check feedback per §4 |
| Saved | Nothing about pupils. Only "last part reached" per lesson for the teacher (localStorage) | Part reached (resume) + Exit ticket score (D7) |
| Chrome | Presenter bar (Back, Read aloud, Next, Show answer, New numbers), part rail | Same rail, smaller bar; no New numbers; Skip as in play |

## 4. Every part's screen anatomy

Common frame (mock): top bar = I Can title, mode pill, **part rail** (5 pills, current filled, done ticked; each a
48 px target; any part reachable, P-ON-1). Stage = **Steps strip** (left, from `routine.steps`, INK-30 numerals) +
**the cell** (right, `.mq-scell`). Bottom = presenter / pupil bar. At 820-1024 the Steps strip moves ABOVE the cell as
one row of numbered chips (L11: steps beside the drawing only when the column is >= 55 mm-equivalent).

- **Warm-up.** 1-3 cells in a row (one per prerequisite skill), each with its library instruction and its own input;
  feedback on Check; unscored. Board: Show answer per cell. A miss shows the prerequisite's "If missed -> Lesson ..."
  line (the Prerequisite Check's own string) in chrome.
- **I do (step reveal).** State k of n: the cell redrawn as after step k (P-LC-9: step k marks grey, earlier black),
  the step's sentence under the drawing (the provider's step text for THIS item, L6), Steps strip row k outlined,
  later rows grey. Next reveals k+1; Back returns. Read-aloud speaks the step sentence on reveal (Pupil: auto; Board:
  on R / Read aloud, auto off by default). After the last step the **Say band** (BD-8, full width under the cell, in
  the cell's ink) fills: "Say: 6 plus 3 equals 9." It is read once, then the board shows **"Say it together"** (chrome)
  and waits. Rule/chant, where the routine has one, shows under Say. No input in I do.
- **We do (hint fade).** 2-3 items. Item 1 starts at rung 1 (next step's marks grey in the cell + sentence), item 2 at
  rung 2 (sentence only), item 3 at rung 3 ("What comes next?" + step highlighted in the Steps strip); a correct item
  moves the next one down a rung, a wrong Check keeps the rung (P-ON-7 "Learn 2"). Hints never fill a slot (P-ON-8).
  Live per-digit feedback (SP-31). Board: the teacher drives the rung with Hint / Next.
- **You do.** The existing practice-card host, unchanged: same cell, Check, **Skip**, wrong-retry and end-of-run rules
  (`game-control.js recordQuestionStatus`, `test-wrong-retry-skip.cjs`), hint ladder on request (rung 2 then 1), 6 items.
  The player embeds the card host; it does not fork it. End of run -> "Exit ticket" (Pupil) / part rail (Board).
- **Exit ticket.** 3 items, Test level (P-ON table: scaffold 0, hints off, on Check once for the set, no retry). Score
  n/3 on an end panel (accuracy only, P-ON-4). **Saves (D7):** `updateSkillProgress(skillId, correct)` per item
  (progress.js, as practice does) + one `state.sessionHistory` entry `{type:'lesson-exit', lessonId, seed, score:n, of:3,
  date}` through the game-flow saver (cap 100 kept). Teacher sees it in the dashboard session list (a "Lesson exit"
  row with the lesson title and n/3) and on the skill's mastery bar; 0-1/3 shows "Re-teach: replay I do" (chrome).
  Board mode never saves an exit score (it is the class, not a pupil).

## 5. Hosts (D5)

| Host | Width | Layout | Digits in cell | Min target |
|---|---|---|---|---|
| Tablet | 820, 1024 | Steps chips above cell, one column | card scale (48 px) | 48 px |
| Computer / Chromebook | 1280, 1366 | Steps strip 300-340 px + cell (mock) | Pupil card scale; Board 104 px | 48 px (Board 64 px) |
| Board / projector | 1920 x 1080 | as 1280, scaled x1.5 (CSS clamp on board vars) | 150 px | 64 px |

No 390 (plan item 7). No horizontal scroll at any host; the cell never shrinks its content (SCC): a drawing that
cannot fit takes the whole stage and the Steps strip collapses to chips.

## 6. Accessibility (D6)

- Keys (Board and Pupil): Right / Space / PageDown = next; Left / PageUp = back (PageUp/PageDown are what presentation
  clickers send); R = read again; H = hint; A = show answer (Board); Esc = leave (confirm). Keys are ignored while focus
  is in a digit input except Enter (Check) and Tab.
- Focus: each reveal moves focus to the new step sentence (`aria-live="polite"` region); part rail is a `nav` with
  `aria-current="step"`; the cell carries `role="group"` + label "Worked example, step k of n".
- TTS: `hints-speech.js` (`speakExplanation`, `stopSpeaking`) and the settings TTS toggle; the spoken text is the step
  sentence and the filled Say line (digits read as numbers, signs via `spokenOp`). Speech stops on every navigation.
- Contrast: cell is pure B&W; chrome text >= 4.5:1. No information by colour alone (done = tick, current = filled + outline).

for 3 lessons (add-within-10, one place-value, one detailed lesson), against these criteria, each >= 8:
1. **Teaching (PEDAGOGY):** one new thing per step; I do steps follow the item; Say filled and spoken; hint fade real; exit is level 0.

## 9. Risks and out of scope

Risks: (a) `workedSteps` is uneven across providers - some give 1 step or none; the player then shows the
anchor's single state and the gate reports the skill (do not invent steps). (b) Templates without `stepState`
(anchors.js `hasStepState`) cannot draw grey marks per step; fall back to the sentence only and list them.
(c) Exit-ticket saving vs P-ON-6 (D7). (d) Board scale on templates measured for cards may overflow; content never
shrinks, the Steps strip collapses instead. (e) The mock's Steps column leaves an empty band below 3 steps (H13): the
build fills it with the Rule / vocabulary chips or narrows the column; it is in the backtest.

Out of scope: phone width; authoring or editing lessons; new lesson content; teacher-side live class response
(clickers per pupil, polls); printing from the player (print stays in the packet); the paused long atomised lessons
(plan item 8); new skills (no SKILL_STANDARDS / search-terms work).
