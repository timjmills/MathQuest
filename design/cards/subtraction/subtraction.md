# Spec card: Column subtraction without regrouping, within 50 to within 1,000,000 (pilot: six SU-C skills)

Pilot family card, scoped to six skills: the no-regrouping rungs of the SU-C ladder (design/catalogue/subtraction.md C4, C6-C9), one stacked problem per boxed cell on the `stack` template with no regroup row. The six differ ONLY in the size of the minuend (within 50, 100, 1,000, 10,000, 100,000, 1,000,000); every other thing that changes is its own step.

## 1. What it teaches

Subtract with the column (standard) algorithm when no column needs regrouping: line the places up, subtract the ones first, then each place to the left. Grades 2-5 (CCSS 2.NBT.B.5, 2.NBT.B.7, 3.NBT.A.2, 4.NBT.B.4; WRM Y2-Y4 column subtraction without exchange). "Within N" bounds the MINUEND (the largest number on the page and the answer's ceiling), never the subtrahend alone.

## 2. Problem types and progression

*From repo sources (PEDAGOGY_STANDARD L-3, design/catalogue/subtraction.md SU-C ladder and rows 145-160, design/PROBLEM_TYPES.md AS rows, the `stack` card); MW4K/IXL research pending logins (Q-H4).*

**Problem types**

- AS-05 vertical subtract with labelled columns (place heads, answer boxes below the rule, no regroup row) — the core item
- AS-11 rewrite a horizontal problem in the grid (alignment, "Do not solve.") — the `sub-setup` page these skills already list
- ragged lengths: a shorter subtrahend lined up under the ones (2d − 1d, 3d − 2d, …) as its own section, never mixed at random with equal lengths
- zero cases as their own section: a 0 digit in the top number (`n − 0`, `0 − 0`), a column that leaves 0 (`n − n`), an answer with fewer digits than the minuend
- AS-15 check a subtraction by adding (`check` line under the stack) — a later step, same drawing

**Progression** (one new thing per step, P-1)

1. within 50 (`sub_50_no_regroup`): 2-digit − 2-digit, minuend ≤ 50, T O heads, answer boxes, no regroup row (L-3 1-4; SU-C C4)
2. within 100 (`sub_100_no_regroup`): the same item, minuend ≤ 99 — ONLY the minuend range changes (C4, second half)
3. the T O heads fade on a dedicated step; the grid and boxes stay (L-3 7)
4. within 1,000 (`sub_1k_no_regroup`): 3-digit minuend, H T O heads back on; 3d − 2d (ragged) first, then 3d − 3d (C6; catalogue row 151)
5. zero cases at 3 digits: a 0 in the top number, a column that leaves 0, an answer with fewer digits (one section, not seeded at random into the plain page)
6. within 10,000 (`sub_10k_no_regroup`): 4 digits, TH H T O heads (C7)
7. within 100,000 (`sub_100k_no_regroup`): 5 digits, TTh heads, comma in numbers and answer (C8)
8. within 1,000,000 (`sub_1m_no_regroup`): 6 digits, HTh heads (C9); then check by adding (AS-15) on any size

### 4a. Core rules — apply every one (15 rules; ✱ = quoted in full, the rest cut at a sentence)

**The stack (WORKSHEET_DESIGN_STANDARD §10.1-10.3, quoted in full)**

- **VA-1** ✱ (WDS) Track count: add / subtract d-digit operands T = d + 1; multiply m-digit by 1-digit T = m + 1; multiply m by n (n >= 2) T = m + n + 1; a unit sign adds 1; each separator adds a 0.3 em track.
- **VA-2** ✱ (WDS) **Operator track**: the leftmost track. The operator (700) sits on the bottom operand's row only, and never moves right to sit beside a shorter operand. The top operand's operator track is empty (the label sits above it).
- **VA-4** ✱ (WDS) **Answer row**: 8 / 10 / 12 mm tall (design value; never below Hw), open space with no lines or boxes on paper. An answer track exists under **every** track including the operator track, so a carry-out digit is written under the operator and the layout never reveals whether one occurs. In Guided cells the answer row shows grey 1 pt ticks, 2 mm long, at each track boundary.
- **VA-7** ✱ (WDS) **Missing-digit items**: when a digit of an operand or of the printed answer is unknown, its track holds a missing-digit box (section 6: dashed, track - 1 mm x Hw) in place of the glyph, on the digit's own row. One unknown digit per item at first, then two. Every other digit of the stack prints as usual, the answer row prints its given digits at working size, and regroup or carry boxes, when on, stay solid (LS-8).
- **VA-10@WDS** ✱ (WDS) **Carry box**: one segment of the regroup strip (SL-12): solid 0.75 pt, slot radius at the strip's ends, width = one track, height 6 / 7 / 8 mm, in a regroup row of 6 / 7 / 8 mm. One above **every column except the ones**, whether or not that column regroups, so the boxes reveal nothing. Black in Model, grey 1 pt in Guided, and present as black structural boxes in Independent when "regroup boxes" is on.
- **VA-11@WDS** ✱ (WDS) **Ones box**: in Model and Guided cells the answer row is one answer strip with a segment per track (SL-12: 0.75 pt, one track x 1.2 Hw). The first Model cell links the ones answer box and the carry box above the tens with a dotted arrow pair (hint) to show "write the ones here, regroup the ten there". Independent cells have an open answer row.
- **VA-12@WDS** ✱ (WDS) Any regroup row forces 0.95 em tracks (TY-21). Strip segments are therefore one 0.95 em track wide: 5.4 / 7.4 / 9.4 mm (the old separate boxes were track - 1 mm, 4.4 / 6.4 / 8.4 mm).
- **VA-13@WDS** ✱ (WDS) Regroup boxes are scratch space: never scored, never marked on screen, never auto-focused (SP-23). **On an answer key AK-2 wins** (owner ruling 2026-09-25): the key FILLS the regroup and carry boxes with the full working - the new value of every regrouped top digit (the 5 over a crossed 6, the 17 over a crossed 7) with the old digit crossed out (VA-23), and every carry over the column that receives it. The boxes stay unscored; only the key writes in them.
- **VA-13a** ✱ (WDS) A subtraction's ONES regroup box holds a two-digit number after a regroup (12, 17), so it is two digits wide (1.5 tracks), overhanging the ones column to the right; the other regroup boxes keep one track (lessons r1, H9).
- **VA-20** ✱ (WDS) When the subtraction regroup scaffold is on, a **headroom row of 8 / 10 / 12 mm** is always present above the top operand (structural). It is open space at S and M.
- **VA-22** ✱ (WDS) **Across zeros**: where the top number contains a run of zeros, one wide box spans the run together with the non-zero digit to its left (the pupil renames 40 tens as 39 tens), and a single box stands over the ones. Box layout is derived from the top number's digits only, never from the answer.
- **VA-23** ✱ (WDS) The pupil crosses out given digits by hand; the sheet never pre-prints a strike in Independent cells. Model cells show the strike as a 0.75 pt solid diagonal and the new value in grey.

**Key, tracks and screen regroup boxes (quoted in full)**

- **AK-2** ✱ (WDS) Answers are Andika **700**, black, at the slot's working size, placed exactly where a pupil would write. Working is shown where the page teaches it: regroup digits in carry boxes (on EVERY key - practice, mixed, independent - over VA-13's scratch rule, owner ruling 2026-09-25), partial products, division work rows, quotient and remainder, hands drawn on clocks, shaded parts shaded, plotted points plotted, rings and check marks drawn at 1.5 pt.

For answer keys, `wrongAnswer`, error analysis, True or False? and Reason It (P-TH-13).

- **D1** SHARED DEFECT (catalogue subtraction.md:145, 148, 151, 154, 157, 160): "wording and colour" — pink / orange legacy column visual and "borrowing" caption on every item — e.g. `buildColumnVisual` (gen-operations.js:504-523)
- **D2** SHARED DEFECT (:145, :148): no place-value letters below grade 3 (`print-generate.js:5815`) although L-3 asks for them — e.g. within 50 / 100 print with no T O heads
- **D3** SHARED DEFECT (:145): `minVal = maxVal/10`, so the small-number and ragged cases never appear; (:148) 2d − 1d ragged items arrive by accident, not as a step — e.g. within 50: every number ≥ 5
- **D4** SHARED DEFECT (:151): 3d − 2d and 3d − 3d mixed at random (research: ragged comes first); misconception "lines the numbers up on the left" — e.g. one page, two lengths at random
- **D5** SHARED DEFECT (:154, :157): no place-value letters above 3 digits; 5-digit numbers, no grid option — e.g. within 10,000 / 100,000 print bare digits
- **D6** SHARED DEFECT (:160): six digits at 2 columns is tight in print — e.g. within 1,000,000 cells crowd the column
- **D7** SHARED FIX on every row (:145-160): "W" — `workedSteps` must be authored; misconceptions SU-M1, SU-M6; Say: "___ minus ___ equals ___."; vocab: ones, tens, line up (then hundreds, place value) — e.g. worked text today: "Line up digits by place value. Subtract each column from the ones." plus a hint restatement
- **SU-M1** takes the smaller digit from the larger in each column (invisible on a no-regroup page: it gives the right answer; it first shows on a regroup item) — e.g. 52 − 38 = 26
- **SU-M7** adds instead of subtracting (does not look at the sign) — e.g. 47 − 23 = 70
- **SU-M6** reverses the numbers when rewriting an across problem in the grid (smaller number on top) — e.g. 68 − 25 set up as 25 over 68
- **M-ALIGN** misaligned places: lines a shorter number up on the left — e.g. 86 − 4 = 46
- **M-ZERO1** zero handling: writes n − 0 as 0 — e.g. 58 − 30 = 20
- **M-ZERO2** zero handling: drops a 0 inside the answer, or writes a leading 0 — e.g. 4508 − 2302 = 226 (or 0246 for 4567 − 4321)
- **M-COMMA** 5-6 digits: misplaces the comma or reads the place wrongly — e.g. 45,678 − 23,456 = 222,22

## 9. Open questions (recommended answers)

1. **Shared defects D1, D2, D5 (legacy pink / orange column visual, "borrowing" caption, place heads missing below grade 3 and above 3 digits): patch the legacy `column-sub` cell or move the six onto `stack`?** Recommended: Move all six onto `stack` (`q.cell`, `regroup: false`) in one change and stop emitting `buildColumnVisual` for them; heads then come from the support level at every size (T O … HTh), which closes D1, D2 and D5 together. No new legacy handler (CLAUDE.md: do not extend the legacy path).
2. **D3 (`minVal = maxVal/10`): what number band does each size deal, given "within N" bounds the minuend?** Recommended: The minuend runs over the size's own digit count up to N (within 50: 21-50; within 100: 51-99, since 100 − n always regroups; within 1,000: 100-999; and so on to 999,999), the subtrahend is any number whose every digit is ≤ the digit above it, and the answer may be small (47 − 42 = 5). Sizes below a band belong to the skill below, so each rung adds one thing: a longer minuend.
3. **D3 / D4 (ragged lengths arrive at random): how do shorter subtrahends enter?** Recommended: As their own section, never at random: a plain option `lengths: same | shorter` (default `same`); at 3 digits and up the Lesson/Guided order is `shorter` first, then `same` (catalogue row 151 research). 2d − 1d is a distinct skill, the NEW `sub_2d_1d` preset (catalogue C3), so it is not an option on `sub_50_no_regroup`.
4. **Zero handling (`n − 0`, `0 − 0`, `n − n` = 0, an answer with fewer digits): seed it into every page or give it its own section?** Recommended: Its own section from 3 digits up (plain option `zeros: on | off`, default off on the plain page; P-1 one new thing). Within 50 / 100 may deal a 0 ones digit naturally (40 − 20) but never seeds it. The key leaves leading answer boxes blank; the pupil is never asked to write a leading 0.
5. **Answer slot shape: how many boxes, and does the box count leak the answer length?** Recommended: One outline with dividers (SL-12), as many boxes as the band's largest minuend has digits, the same on every item of the section; never the item's own answer length (that would give away "the answer has 1 digit"). Commas print in the minuend and subtrahend from 5 digits up and sit in a narrow fixed gap in the answer row, not in a box.
6. **D6 (six digits at 2 columns is tight): shrink, or fewer columns?** Recommended: Never shrink (SCC-T4): the capacity rows decide. At L, 5- and 6-digit items take 1 column if the two-column cell is narrower than the stack plus gutter; at S / M they keep 2. The capacity check is a gate number, not a judgement.
7. **SU-M1 (smaller from larger) is invisible on a no-regroup page. Seed regroup non-examples here (P-10)?** Recommended: No: the skill's name promises no regrouping and `ws-content-audit` holds it to that. The non-examples and the decide page live on the `_mixed` skills (SU-R R2). Here the key's `wrongAnswer` is built from SU-M7 (adds), M-ALIGN (left-lined) and M-ZERO, which do show on these items.
8. **MW4K / IXL research is pending logins (Q-H4). Sign now?** Recommended: Yes, sign now; add the research to section 2 when the logins work, and re-sign only if the problem types or progression change.
