## 1. What it teaches

Subtract with the column (standard) algorithm when no column needs regrouping: line the places up, subtract the ones first, then each place to the left. Grades 2-5 (CCSS 2.NBT.B.5, 2.NBT.B.7, 3.NBT.A.2, 4.NBT.B.4; WRM Y2-Y4 column subtraction without exchange). "Within N" bounds the MINUEND (the largest number on the page and the answer's ceiling), never the subtrahend alone.

## 2. Problem types and progression

**Problem types**

- AS-05 vertical subtract with labelled columns (place heads, answer boxes below the rule, no regroup row) — the core item
- AS-11 rewrite a horizontal problem in the grid (alignment, "Do not solve.") — the `sub-setup` page these skills already list
- ragged lengths: a shorter subtrahend lined up under the ones (2d − 1d, 3d − 2d, …) as its own section, never mixed at random with equal lengths
- zero cases as their own section: a 0 digit in the top number (`n − 0`, `0 − 0`), a column that leaves 0 (`n − n`), an answer with fewer digits than the minuend
- AS-15 check a subtraction by adding (`check` line under the stack) — a later step, same drawing

**Progression** (one new thing per step, P-1)

1. within 50 (`sub_50_no_regroup`): 2-digit − 2-digit, minuend ≤ 50, T O heads, answer boxes, no regroup row (L-3 1-4; SU-C C4)
2. within 100 (`sub_100_no_regroup`): the same item, minuend ≤ 99 — ONLY the minuend range changes (C4, second half)
3. the T O heads fade on a dedicated step; the grid and boxes stay (L-3 7)
4. within 1,000 (`sub_1k_no_regroup`): 3-digit minuend, H T O heads back on; 3d − 2d (ragged) first, then 3d − 3d (C6; catalogue row 151)
5. zero cases at 3 digits: a 0 in the top number, a column that leaves 0, an answer with fewer digits (one section, not seeded at random into the plain page)
6. within 10,000 (`sub_10k_no_regroup`): 4 digits, TH H T O heads (C7)
7. within 100,000 (`sub_100k_no_regroup`): 5 digits, TTh heads, comma in numbers and answer (C8)
8. within 1,000,000 (`sub_1m_no_regroup`): 6 digits, HTh heads (C9); then check by adding (AS-15) on any size

**The stack (WORKSHEET_DESIGN_STANDARD §10.1-10.3, quoted in full)**

- **VA-2** ✱ (WDS) **Operator track**: the leftmost track. The operator (700) sits on the bottom operand's row only, and never moves right to sit beside a shorter operand. The top operand's operator track is empty (the label sits above it).
- **VA-4** ✱ (WDS) **Answer row**: 8 / 10 / 12 mm tall (design value; never below Hw), open space with no lines or boxes on paper. An answer track exists under **every** track including the operator track, so a carry-out digit is written under the operator and the layout never reveals whether one occurs. - **VA-7** ✱ (WDS) **Missing-digit items**: when a digit of an operand or of the printed answer is unknown, its track holds a missing-digit box (section 6: dashed, track - 1 mm x Hw) in place of the glyph, on the digit's own row. One unknown digit per item at first, then two. Every other digit of the stack prints as usual, the answer row prints its given digits at working size, and regroup or carry boxes, when on, stay solid (LS-8).
- **VA-10@WDS** ✱ (WDS) **Carry box**: one segment of the regroup strip (SL-12): solid 0.75 pt, slot radius at the strip's ends, width = one track, height 6 / 7 / 8 mm, in a regroup row of 6 / 7 / 8 mm. The first Model cell links the ones answer box and the carry box above the tens with a dotted arrow pair (hint) to show "write the ones here, regroup the ten there". - **VA-12@WDS** ✱ (WDS) Any regroup row forces 0.95 em tracks (TY-21). Strip segments are therefore one 0.95 em track wide: 5.4 / 7.4 / 9.4 mm (the old separate boxes were track - 1 mm, 4.4 / 6.4 / 8.4 mm).

- **VA-22** ✱ (WDS) **Across zeros**: where the top number contains a run of zeros, one wide box spans the run together with the non-zero digit to its left (the pupil renames 40 tens as 39 tens), and a single box stands over the ones. ## 6. Misconceptions

For answer keys, `wrongAnswer`, error analysis, True or False? and Reason It (P-TH-13).

- **D1** SHARED DEFECT (catalogue subtraction.md:145, 148, 151, 154, 157, 160): "wording and colour" — pink / orange legacy column visual and "borrowing" caption on every item — e.g. `buildColumnVisual` (gen-operations.js:504-523)
- **D2** SHARED DEFECT (:145, :148): no place-value letters below grade 3 (`print-generate.js:5815`) although L-3 asks for them — e.g. within 50 / 100 print with no T O heads
- **D3** SHARED DEFECT (:145): `minVal = maxVal/10`, so the small-number and ragged cases never appear; (:148) 2d − 1d ragged items arrive by accident, not as a step — e.g. within 50: every number ≥ 5
- **D4** SHARED DEFECT (:151): 3d − 2d and 3d − 3d mixed at random (research: ragged comes first); misconception "lines the numbers up on the left" — e.g. one page, two lengths at random
- **D5** SHARED DEFECT (:154, :157): no place-value letters above 3 digits; 5-digit numbers, no grid option — e.g. within 10,000 / 100,000 print bare digits
- **D6** SHARED DEFECT (:160): six digits at 2 columns is tight in print — e.g. within 1,000,000 cells crowd the column
- **D7** SHARED FIX on every row (:145-160): "W" — `workedSteps` must be authored; misconceptions SU-M1, SU-M6; Say: "___ minus ___ equals ___."; vocab: ones, tens, line up (then hundreds, place value) — e.g. worked text today: "Line up digits by place value. Subtract each column from the ones." plus a hint restatement
- **SU-M1** takes the smaller digit from the larger in each column (invisible on a no-regroup page: it gives the right answer; it first shows on a regroup item) — e.g. 52 − 38 = 26
- **SU-M7** adds instead of subtracting (does not look at the sign) — e.g. 47 − 23 = 70
- **SU-M6** reverses the numbers when rewriting an across problem in the grid (smaller number on top) — e.g. 68 − 25 set up as 25 over 68
- **M-ALIGN** misaligned places: lines a shorter number up on the left — e.g. 86 − 4 = 46
- **M-ZERO1** zero handling: writes n − 0 as 0 — e.g. 58 − 30 = 20
- **M-ZERO2** zero handling: drops a 0 inside the answer, or writes a leading 0 — e.g. 4508 − 2302 = 226 (or 0246 for 4567 − 4321)
- **M-COMMA** 5-6 digits: misplaces the comma or reads the place wrongly — e.g. 45,678 − 23,456 = 222,22
