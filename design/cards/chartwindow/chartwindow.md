# Spec card: The number chart window (`chartwindow`) and its band to 120 (build-list `chart_120`)

Generated by `node tests/scripts/ws-spec-card.mjs --template chartwindow` from `design/cards/chartwindow/card.json` and the repo. Do not edit by hand: edit card.json and regenerate. Builders read this card; critics keep reading the full standards and RUBRIC.

A window cut from a number chart, rows of ten (across is one more, down is ten more), with one to seven empty squares the pupil writes in. Each empty square is a whole chart square with a 1.5 pt border: the writing place. This card signs the template as it stands and the one change the build list asks of it: `chart_120`, a band 120 on composing:hundreds_chart_fill whose window always crosses 100 (rows 91-100 / 101-110 / 111-120), with three-digit numbers in the squares at the working digit size, and a whole chart of 12 rows. Paper, key and the three screen hosts are one drawing.

## 1. What it teaches

Count, read and write numerals to 120 starting at any number, across 100 (1.NBT.A.1, M.EE.1.NBT.1; lesson G1-Y2.B1 "Count on to 120", design/lessons-first/BUILD_QUEUE.md row 13, QUEUE `G1|-|countonto120`). The chart's two patterns: along a row one more, down a column ten more (1.NBT.C.5 in use). number_chart_fill: the same window on the chart of the hundreds and thousands (101-200 ... 5,001-10,000; 2.NBT.A.2 / 4.NBT.A.2 counting within 1,000 and beyond); it never crosses 100 (its first band starts at 101).

## 2. Problem types and progression

The sites deal 8-30 blanks on one dense whole chart; we keep the window (a page of 4-6 windows, 1-3 squares each) and the whole chart as one cell to a page, as the design standard sets.*

**Problem types**

- Fill the window 95-115 (band 120): a 3 x 5 window cut from rows 91-100, 101-110, 111-120, any five columns; 1 to 3 empty squares dealt (Empty boxes 1-7 when chosen), each with a printed number beside it in its row or column.
- What comes after 109? (band 120): a scatter gap at 110 or 111 with 109 / 110 printed on its left; the pupil writes the number after, crossing the decade. The dealer biases band-120 gaps so at least one item in three sits at 100, 101, 110 or 111 (the crossings).
- Count on from 98 (band 120): the run along a row (gaps=row) inside rows 91-120, a printed number at each end; counting on ACROSS the row break (98, 99, 100, 101 on one line) is not a chart task: it is `counting:number_seq_fill`, the lesson's other skill.
- Fill the row 111-120 (band 120, grid=rows): three whole rows of ten (91-120), a run of up to 8 empty squares along the bottom row, 111 and 120 printed (the run keeps one square in from each edge).
- Whole chart (grid=whole, band 120): the 1-120 chart, 12 rows of ten, one cell to a page, gaps scattered / a row / a column / every other square.
- Bands below 120 (10 ... 100) and number_chart_fill (101-200 ... 5,001-10,000) unchanged: the same window, the same gap rules.

**Progression** (one new thing per step, P-1)

1. O2 number size: band 100 (the 1-100 chart) -> band 120 (the window across 100). The build list's '90-110 -> 100-120' rung is the dealer's position inside band 120, not a second band (open question 2).
2. O3 support: gaps scattered with a printed neighbour on every side it can have one -> a run along a row (count on by 1 from the printed number at its left end) -> a run down a column (count on by 10 from the number above). The row's start stays printed (open question 3).
3. O6 appearance: a window (3 x 5) -> three whole rows of ten -> the whole chart (one cell to a page).
4. One change a step (P-1): the band changes the numbers only; the window, the gap rules and the response (write the number in the square) stay.
